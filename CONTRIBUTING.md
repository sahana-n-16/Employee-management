
# Contributing to Workfolio

Thank you for contributing to the Workfolio Employee Management System.

## 1. Project Structure

- frontend/ - React application
- backend/ - Spring Boot application
- docs/ - Project documentation

## 2. Branching Guidelines

- master: Main stable branch.
- Each team member should create a separate feature branch.
- Do not directly push changes to master.

## 3. Branch Naming Convention

Use the following format:

feature/your-feature-name

Examples:
- feature/authentication
- feature/employee-management
- feature/admin-dashboard
- feature/attendance-management

## 4. Commit Guidelines

Write clear and meaningful commit messages.

Examples:
- Add login page UI
- Implement employee registration API
- Fix authentication validation
- Update dashboard styling

## 5. Pull Request Guidelines

1. Push your feature branch to GitHub.
2. Create a Pull Request into master.
3. Ask another team member to review your changes.
4. Resolve conflicts if any.
5. Merge after approval.

## 6. Important Rules

- Do not commit node_modules or target folders.
- Do not upload passwords, API keys or secrets.
- Test your changes before pushing.
- Avoid modifying another member's work without discussion.

## 7. Team Collaboration

All members should communicate before modifying shared files and coordinate changes to avoid merge conflicts.
